<details>
<summary>Artifact 內容摘要：維基來源評級命中評估（資料期間 2026-05-13～10-13）</summary>

> 原始 HTML 存檔：[artifacts/20261020-MkCyx4YhkfD8Y28Qu14qWT.html](./artifacts/20261020-MkCyx4YhkfD8Y28Qu14qWT.html)（Mermaid 圖需連線 runtime，離線只會顯示原始碼）

**結論：** 中文維基《來源評級/列表》（363 筆）約命中四成的 cofacts.ai 出處；英文 WP:RSP 只再多 2–3 個百分點。影響最大的是維基百科本身（23% 草稿引用維基，而兩個列表都評為「通常不可靠」）；約一半命中落在「依主題分評級」的條目，分歧點多是政治報導，所以工具不能只回傳基準評級，要回傳摘要讓模型依主題判斷。writer 已會避開「應停用」來源（入選率 5%），評級對這類的邊際效果不大。

**第一部分：研究（資料取自 Langfuse TOOL observation）**
- 命中度：草稿 `references` 3,252 個 URL 中 41.2% 命中中文列表、英文列表 13.2%、合計 44.0%；765 份草稿中 588 份至少一個出處命中。investigator 搜尋結果命中 39.8%（合計 41.9%）、verifier 讀過的頁面 44.4%（合計 46.2%）。

**第二部分：技術討論（ADK 1.26.0）**
- 現況：investigator（`google_search` + `append_grounding_sources`）與 verifier（`url_context` + `append_url_context_sources`）都以 AgentTool 回傳 `{content, sources:[title,url]}`，經 writer 的 `_normalized_response`。
- 提案 A：包成 SequentialAgent，後接便宜模型 `source_rater`，替 sources 補 `rating_hint`。before_agent_callback 先做網域比對：investigator 呼叫 69% 命中依主題評級條目需要 rater，31% 可略過（13% 沒命中、18% 單一評級）；verifier 為 52%／48%；評級摘要中位數約 700 字（p90 約 1,700 字，verifier 約 270 字）。ADK 注意事項：`AgentTool` 取最後有內容的 event，故最後一步必須輸出完整 `{content, sources}`（含 `_search_widget_html`）；rater 不能設 `output_schema`（會沿 `sub_agents[-1]` 驗證），改用提示要求 JSON 並寬鬆解析；before_agent_callback 回傳 Content 可略過該 agent；子 session 的 `state_delta` 會流回 writer session，中間 key 加 `temp:` 前綴（AgentTool 間轉發行為尚未實測）；SequentialAgent 要沿用 `investigator`/`verifier` 名稱，內層 LlmAgent 改名；investigator 的 `[SYSTEM]` 重試字串與 verifier 無 grounding 的原始文字，rater 原樣放行；若用 Haiku 5.5 要加 `anthropic[vertex]` 依賴、Model Garden 啟用，且 `instrumentation.py` 的 usage 對應是依 Gemini 寫的，Langfuse 計價要另確認；rater 失敗或逾時退回不加提示。
- 其他做法：B 離線把每個條目摘要壓成「主題→評級→一句提示」，由現有兩個 callback 查表附上（延遲零、最好測，但 writer 要自己對照主題、context 變長）；C 在 writer `after_tool_callback` 呼叫 rater（結構不動，但 Langfuse 要手動加 span）；D 由 verifier 在報告中依主張判斷評級（不增加模型呼叫，verifier 手上有主張原文與頁面內容；但須把「是否支持」與「來源可信度」分開輸出，否則有支持但來源弱的主張會被打 ✗；investigator 階段沒提示；覆蓋率取決於 writer 是否真的呼叫 verifier）；E `check_source_reliability(urls)` 工具由 writer 決定何時查；F `draft_factcheck_response` 送出時硬性檢查（例如 claim_sources 指向維基就退回）。
- 建議路線：先做 B + F（B 的離線提示也是 A/C 需要的資料，F 直接處理量最大的維基引用），上線後用 Langfuse 觀察「草稿引用維基比例」與「政治類主張只靠政治報導通常不可靠來源佐證的比例」；若 writer 常套錯主題再升級 A 或 C。另一條路線是 D + F（investigator 階段可用 B 的查表附簡短提示）。
- 技術面待決：評級在哪一段加入（A/B/C/分階段）、依主題判斷由誰做（rater／writer／verifier）、rater 用哪個模型（Haiku 5.5 或輕量 Gemini）、評級資料放哪裡與如何每週同步（Wikimedia 對雲端 IP 的 MediaWiki API 會回 429，這次改用 `action=raw` 慢速抓取，正式同步需固定主機與帶聯絡資訊的 User-Agent）、怎麼驗證效果（用歷史 trace 建 Langfuse dataset）。決定後依專案慣例寫決策紀錄（`docs/decisions/`）。
- 方法限制：中文列表只缺「看中國」（被限流）；網址比對採網域或子網域；入選率以同 trace 內 URL 完全比對，換網址形式會被算成未入選。

</details>

- **原委：** writer 挑出處目前只靠模型自己判斷。中文維基《來源評級/列表》有 363 個來源的社群共識評級，想評估能否用它提示 writer 哪些出處適合作為佐證。
- **研究：** 比對近五個月的 Langfuse trace，結果如下：
  - **命中度：** 中文列表涵蓋約 41% 的草稿出處，英文 WP:RSP 只再多約 3 個百分點。
  - **維基引用：** 影響最大的是 23% 的草稿引用了維基百科本身，而維基把自己評為「通常不可靠」。
  - **依主題分評級：** 約一半的命中是「依主題分評級」的媒體（中時、聯合、自由等），差異集中在政治報導，所以不能只看基準評級。
- **提案：** 有三個方向待討論：
  - **A：** 在 investigator / verifier 後接便宜模型（rater），補上評級提示；
  - **B + F：** 離線寫好提示、用現有 callback 查表附上，再加上草稿送出時擋下維基引用；
  - **D + F：** 由 verifier 依主張判斷評級，並把「是否支持」和「來源可信度」分開輸出。

  會議要決定的是採用哪個方向、主題判斷交給誰做，以及評級資料怎麼同步。
